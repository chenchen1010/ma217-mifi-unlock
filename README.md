# MA217 随身 WiFi：自备电信卡、重启保持与限速分析

从一台自有 MA217 的原机备份出发，定位外置 SIM 认证、厂家自动切卡和设备双向限速，制作最小应用补丁，并完成实机回读、上网和重启验证。

**最终设备运行的是修改版固件。** 过程曾因擦除长度取整而损坏相邻程序；先用原始备份恢复，回读确认原固件一致后，再写入修正的补丁。原始备份、恢复过程和最终修改版不能混为一谈。

仅验证过以下一台设备的软件组合；外壳型号相同不代表可以互刷。

| 项目 | 已验证值 |
|---|---|
| 外壳型号 / 模组型号 | MA217 / MA216 |
| 主板 | `LBF1A_N10` |
| 屏蔽罩标签 | `ML358A-B-FMF` |
| 固件 | `LBF1ANT_N10_WH_2ESIM_V001`，2025-08-18 |
| 平台 | ASR1803 / Falcon，bootloader 3311 |
| 正常 USB | `1286:4E3D`，RNDIS、AT、Diag |
| 启动下载 USB | `2ECC:3001`，WTPTP WinUSB |
| 外置卡 | 中国电信 USIM，slot 2 |
| 实机环境 | Windows x64，Python 3.11 |

## 下载什么

[下载 v1.0.0 的固件附件](https://github.com/chenchen1010/ma217-mifi-unlock/releases/tag/v1.0.0)。附件包含：

- `OSLO-original.bin`：从原机提取、未改动的 **OSLO 程序镜像**，4,259,840 字节。
- `OSLO-unlocked.bin`：关闭上述三个控制入口后的同一程序镜像，大小相同。
- `SHA256SUMS.txt`、`firmware-manifest.json`：完整性和补丁位置说明。

**这两份是程序镜像，不是可直接整片刷入的 8 MiB 备份，也不是网页升级包。** `OSLO` 原位于 Flash `0x40000..0x450000`，本项目实际只改其中一个 AP 压缩槽。刷写包必须由自己的原始备份生成，保留自己的身份、校准、配置和验证数据。

整机备份中已实际发现设备 / SIM 标识，包括 ASCII、BCD 和 MAC 二进制形式，因此不公开原始整机 dump、诊断流、运行配置或整机修改版。它们也不适合给另一台设备互刷。发布的程序镜像及全部解压程序段未命中本机已知身份值；这不是对任意第三方固件的隐私认证。

## 使用入口

首次操作请从 [完整复现步骤](docs/REPRODUCE.md) 开始；需要理解为何这样做，见 [成功路径与踩坑](docs/LESSONS.md)。已发生启动异常时看 [恢复与验收](docs/RECOVERY.md)。

可以把仓库交给 AI 编程助手，并发送：

> 请按本仓库的复现文档检查我的设备是否匹配，先完成原机备份和离线验证，再协助我使用自备 SIM 卡。

安装、离线验证和实机使用是三个不同阶段。运行测试或打印 `preflight=true` 不代表设备已刷好；只有回读、正常启动、活动 SIM 身份和指定网络出口的实际 HTTPS 都通过，才能算对应环节成功。

Windows 的 WinUSB 回读 / 写入流程在本机验证过。macOS / Linux 可以阅读源码、校验和离线构建；本仓库没有声称它们支持同一套 USB 实机刷写。不要在其他平台跳过驱动层检查照抄 Windows 命令。

## 实际改动

解压后的 AP 基址为 `0x064a2000`，只修改 3 处、合计 6 字节：

| 地址 | 原字节 → 新字节 | 作用 |
|---|---|---|
| `0x065788a6` | `2048` → `7047` | 在创建 SIMAUTH 任务前返回 |
| `0x0656e584` | `0022` → `7047` | 在注册 MAINSYN 回调前返回 |
| `0x0657ccbe` | `60b9` → `0020` | 进入原有关闭双向流控的分支 |

认证任务曾返回失败并禁用外置卡；云端同步曾触发 `USIM → eSIM1`。仅在网页选外置卡、改 APN 或阻断单个域名，未能解决这台设备的重启持久性。补丁保留原网页界面、驱动和蜂窝协议栈。

发现的限速初始化从 `hcsi.limit_speed` 取值，没有按卡槽区分；外置卡也会经过这条全局控制路径。这里只关闭已定位的设备控制，不能改变运营商套餐、基站拥塞或射频条件。

## 实机结果与边界

2026-10-29，Asia/Shanghai：

| 验证 | 结果 |
|---|---|
| 原固件恢复 | 固件 `0..0x540000` 与原备份逐字节一致，正常启动 |
| 最终补丁回读 | AP 槽与候选完全一致，槽外固件和 WebUI 不变 |
| 外置卡 | 活动卡与插入的电信卡一致，禁用标志 0 |
| 认证 / 切卡补丁重启后 | 约 5 分钟、90 次状态采样一致，WiFi HTTPS 10/10 通过 |
| 追加限速补丁后重启 | uptime 从 48 降到 10，自动使用外置卡，未重新选卡；WiFi HTTPS 通过 |
| 下载对比，每次 16 MiB | 补丁前 16.68 Mbps；补丁后 25.88 Mbps；再次重启后 25.87 Mbps |
| 最终持续观察 | 149.4 秒前有效状态持续为外置卡、6/6 次 HTTPS 通过；随后用户拔走设备，未完成该轮 5 分钟窗口 |

最后一次断开已由用户确认是拔走设备，不能记为自动重启故障；同样不能把未完成的观察写成完整五分钟通过。测速入口相同，CDN 最终节点不同，属于现场对比，不是受控实验，也不保证所有地点都能达到相同速率。没有进行多天稳定性或全运营商验证。

完整原始证据留在本地；公开的是 [脱敏结果摘要](evidence/acceptance.json)。整理后的脚本经过离线重建和原机 ARM 解码 / 擦除路径模拟，修改包与恢复包哈希与已实机使用的包一致；参数化后的整套流程尚未在第二台设备复测。
