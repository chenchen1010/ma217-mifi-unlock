# Working on this repository

- Entry order: README.md -> SKILL.md -> facts/SUPPORTED_DEVICE.md. SKILL.md owns routing: compatible devices use docs/REPRODUCE.md and docs/RECOVERY.md; incompatible or unidentified devices continue with docs/RESEARCH_WORKFLOW.md. Do not invent a second flow in README or a chat prompt.
- A repository link starts environment inspection and read-only identification. Use the human's session authorization for later device actions; prepare concrete packages and evidence before asking for any missing write authorization.
- No subagents without the human user's approval.
- Keep raw backups, identifiers, calibration data, diagnostic streams and local evidence under ignored artifacts/. Never publish them.
- Only one hardware/firmware profile is verified. An observed hardware, firmware, bootloader, header or image-hash mismatch means INCOMPATIBLE for this profile: stop applying this patch, retain the mismatch and actively continue justified read-only identification, extraction research and offline analysis. INCOMPATIBLE is not task completion. Missing evidence is UNKNOWN or PENDING. Do not weaken hashes, remove assertions, use Python -O or silently generalize offsets.
- Read-only research must not invoke this profile's noop/loader, patch generation or flash commands on another device. A read-only command still needs evidence that its protocol and semantics fit the target. Continue independent routes when one is blocked; report a specific blocker only after useful available work is done.
- For the verified profile, write only the aligned 0x260000..0x320000 range; these addresses do not apply to research targets. No factory reset, identity edits or whole-chip erase. A new profile needs its own backup, layout, erase-semantics, recovery and validation evidence before a separate write workflow.
- Keep recovery and original backup intact. Execute the real OBMI erase-wrapper model, not a mock that assumes request length equals erased length.
- Rebuild and decoder checks are offline evidence. Claim actual success only from readback, normal boot, active external SIM and interface-bound Internet checks.
- Report human unplug/restart events separately from device instability. Do not inflate partial observation into completed duration.
- The user can authorize device operations in the session; do not ask for duplicate permission once scope is clear.
- Tool attribution: facts/REA_USAGE.md is the source for REA's actual contribution. Format recognition or JavaScript parsing is not firmware extraction or complete decompilation. REA is optional for this reproduction.
- Documentation acceptance: README begins with a short copyable prompt; platform scope is explicit; every workflow stage has local evidence and a stop/continue branch; a mismatch stops reuse, not all research; original dumps stay private; historical/partial results cannot replace live acceptance. Keep release binary hashes and the flash algorithm unchanged for documentation-only updates.
